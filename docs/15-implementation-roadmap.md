## 15.1 Sequencing Notes

- Phase 3 (design) is deliberately placed before feature phases so every subsequent screen is built against a resolved, shared component library rather than one-off styling per feature — but it can start on tokens alone before the screenshot re-upload lands, since the token set is already usable.
- Phases 4–11 roughly track the 28 workflows in dependency order (a project needs a JD before requirements, requirements before a scorecard, a scorecard before scoring, scoring before review, review before shortlisting).
- Phase 12 (POC/analytics) is placed after the core pipeline is real, not before — the POC in [[14-poc-specification]] needs the actual scoring/evidence pipeline to be meaningful; a fake demo would undermine the "defensible" positioning the whole product depends on.
- Mobile (13) intentionally follows the full web pipeline, matching the client's explicit instruction ("Create an Expo React Native mobile application after the core web platform is functional").
